## B. Explanation task — what "significance" is and why it is so large

`sig_weight` (shown as **Pathway score**) is computed in
`03_network/rebuild_network_enrichment.py` (~line 201) as:

```
sig_weight = sum( -log10(FDR_p)  for p in shared KEGG pathways between compound & disease )
```

So a value like **51.665 is NOT a p-value of 10⁻⁵¹.** It is the **sum of −log10(FDR)
across ~22 individually FDR-significant shared pathways** (each pathway contributes a
term > 1.3, i.e. FDR < 0.05; summing ~22 of them lands near 30–50). It is an *aggregate
strength* measure — "how many strongly-enriched pathways do this compound and disease
have in common," not the significance of a single test.

**The underlying calculation is correct.** The problem was purely presentation: labeling
an additive weight as "significance" invites reading it as one extreme p-value. Fixed by
renaming it **Pathway score** everywhere and adding the summed-−log10(FDR) explanation.

## C. Explanation task — reference audit (do the PubMed links work and match?)

**All 117 distinct PubMed IDs referenced by the 59 curated edges resolve to real records
(0 broken links)** — validated via NCBI E-utilities `esummary`.

**Topical relevance:** an automated title screen found 53/59 edges whose reference title
mentions the compound or disease; the 6 without a title-level hit were deep-checked against
their PubMed abstracts:

| Edge | PMID | Verdict |
|------|------|---------|
| Hydrogen sulfide → Asthma | 22357138 | ✅ Solid — "households with…H₂S were twice as likely to report doctor-diagnosed asthma" |
| Sulfur dioxide → Pneumonia | 25115710 | ✅ Solid — "SO₂ exposure…increased risk of pneumonia and influenza" |
| Nicotine → Bronchitis | 27806211 | ⚠️ Indirect — e-cigarette → bronchitic symptoms; nicotine implied, not named |
| Phenobarbital → Asthma | 208429 | ⚠️ Weak — phenobarbital is an inert ingredient in a combo asthma tablet; no phenobarbital–asthma link |
| Capsaicin → Pneumonia | 22575871 | ❌ Mismatch — paper is about *naringin* in a *chronic bronchitis* model; mentions neither capsaicin nor pneumonia |
| Theophylline → Pneumonia | 1541177 | ❌ Mismatch — paper is "Role of ciprofloxacin in fatal seizures"; mentions theophylline, not pneumonia |

**Conclusion:** every reference link is valid and loads. ~3/59 curated edges (~5%) carry a
**CTD curation artifact** — a PMID where the chemical only co-occurs (combo-drug ingredient,
a method's challenge agent) rather than being the studied exposure for that disease. These
are **source-data issues in CTD, not code bugs**, so they were flagged rather than silently
altered. If you want, we can add a lightweight "reference confidence" flag or drop these
specific PMIDs from the curated set.

## D. New module — "Your data" network builder (revertible)

A new nav item **Your data** (`/your-data`) lets a user upload a CSV and get a
chemical–disease network drawn back. It auto-detects two input shapes:

1. **Association list** — CSV has a chemical column *and* a disease column (optional
   `weight` / `link_type`). Drawn exactly as supplied; nothing inferred.
2. **Compound list** — CSV has only a chemical column. Each compound is resolved on
   PubChem and scored by the trained model against the six diseases; an edge is drawn
   wherever the predicted likelihood ≥ a slider threshold. **These edges are predictions**
   (and any that also match a curated CTD pair are tagged `known` with references).

### Files (this feature is intentionally isolated)
- **`04_backend/app/user_network.py`** — new, self-contained `APIRouter`
  (`POST /api/user-network/build`). Reuses `app.score` for the compound-list path; does
  not modify any existing engine.
- **`05_frontend/src/pages/UserNetwork.jsx`** — new page with its own Cytoscape instance
  using the built-in `cose` layout (deliberately not fcose, so it never touches the
  Explorer's extension registration).
- Small wiring, each marked `revertible`: two lines in `04_backend/app/main.py`
  (import + `include_router`), one route in `App.jsx`, one nav link in `Brand.jsx`, one
  `userNetwork` method in `api.js`.

### To revert completely

2. Delete `05_frontend/src/pages/UserNetwork.jsx`.
3. Remove the marked lines in `App.jsx`, `Brand.jsx`, and `api.js`.

### Live PubMed scouring (`04_backend/app/pubmed_scan.py`, revertible add-on)
New endpoint `GET /api/pubmed/scan?compound=&disease=&similar=`. It is **not a scraper of
our data** — it live-queries PubMed E-utilities (esearch + efetch XML), pulls each hit's
**abstract**, and keeps only papers whose abstract actually co-mentions the compound (or a
PubChem name synonym — the "similar" names) **and** the disease (whole-token match, so "PM"
≠ "symptoms"). Every result is tagged `source: "scoured"`.

In the disease-expansion panel, references are now split into two labelled blocks:
**CTD** (curated, from the shipped dataset) and **scoured** (on-demand live PubMed, behind a
"Scan PubMed for <compound>" button). Synonym matches are shown as *(via "…")*, plus an
"N of M hits verified" line.

**Structural analogs (follow-up).** An "include structural analogs" checkbox adds a real
2D-similarity search: the backend resolves the compound to a PubChem CID, calls
`fastsimilarity_2d` to get structurally similar compounds, fetches their names, and folds
them into the PubMed query. Each result is now tiered by match specificity —
`exact` (the compound) › `synonym` (a PubChem name synonym) › `analog` (a structurally
similar compound), and analog hits render as *(structural analog: <name>)*. Verified with
`benzo(a)pyrene`: analogs found were Anthracene, Phenanthrene, Pyrene, Benz(a)anthracene,
Benzo(ghi)perylene (all PAHs), disclosed in the summary line. So "similar" now means both
name-synonyms *and* structural analogs, not just synonyms.

**Why this matters (the "just mentions the compound" problem):** CTD references are trusted
verbatim and ~5% are loose (see §C). Scoured references are weaker than curation in
authority but stronger in one specific way — we verified the abstract co-mentions both terms.
Co-mention still is not proof of association (a human must read it); the UI says so.

`pubmedScan` method in `api.js` (the Analyze UI degrades gracefully — the Scan button just
errors if the endpoint is gone).

Verified: `benzo(a)pyrene + Asthma` → 10/10 abstract-verified hits (incl. CAS 50-32-8 and
`benzo[a]pyrene` synonym matches), real titles, CTD + scoured blocks both rendering, no
console errors.
